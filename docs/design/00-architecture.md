# 00 全体アーキテクチャ（草案）

作成日: 2026-10-13
状態: 草案。設定スキーマと命令一覧は次の設計書で確定する。

## 1. 目的

利用者は WebChat で会話するだけで、手元の秘書 Claude Code が会話内容から仕事用 Mac と
私用 Mac を使い分け、それぞれの Claude Code に作業を進めさせる。
GUI 操作が必要な作業は各 Mac の純正 Computer Use（以下 CU）で行う。
最終的に OSS として公開するため、設定は利用者が設定画面から行い、コードには埋め込まない。

## 2. 部品

| 部品 | 動く場所 | 正体 | 役割 |
| --- | --- | --- | --- |
| WebChat UI | ブラウザ | 静的ページ | 利用者との唯一の窓口。会話、承認、停止、設定画面 |
| ハブ | ハブ Mac | 常駐プログラム兼 秘書用チャネルサーバー | WebChat の配信、ワーカーとの常時接続の受け口、秘書 Claude への流し込み、秘書向けツールの提供 |
| 秘書 Claude | ハブ Mac | Claude Code の対話セッション | 会話内容からワーカーとプロジェクトを選び、ハブのツールで仕事を投げ、結果を利用者へ返す |
| ワーカー常駐プログラム | 作業 Mac | 常駐プログラム（Claude ではない） | ハブへ接続しに行く。Claude Code セッションの起動・再開・停止、tmux 画面の読み取りとキー送信、結果の中継 |
| ワーカーチャネル | 作業 Mac | Claude Code が起動するチャネルサーバー | 自分のセッションに指示を流し込み、返信ツールで結果をワーカー常駐プログラムへ渡す。承認要求の中継も担う |

Claude 同士は直接通信しない。すべてハブと常駐プログラムが仲介する。

## 3. 接続の向き

```text
WebChat ──HTTP/SSE──► ハブ ◄──常時接続（ワーカーから発信）── ワーカー常駐プログラム
                       │                                      │ localhost
                       ▼ stdio                                ▼ stdio
                  秘書 Claude                    ワーカーチャネル ─ Claude Code セッション
```

- Channels は「チャネルサーバーを起動した Claude Code の 1 セッションに出来事を流し込む」一方向の仕組み。
  セッションから外へ送るのは返信ツールなどの通常のツール呼び出しで行う
- 作業 Mac はハブへ自分から接続する（接続型）。無人設置でもルーターの設定が不要で、設置場所が変わっても動く
- ワーカーチャネルはセッションごとに 1 プロセス。常駐プログラムがそれらを 1 本の接続にまとめてハブへ渡す

## 4. 主な流れ

### 4.1 会話から作業まで

1. 利用者が WebChat に書く。ハブが秘書 Claude のセッションへ `<channel>` として流し込む
2. 秘書 Claude がワーカーとプロジェクトを選び、`session_send`（必要なら先に `session_create`）を呼ぶ
3. ハブが該当ワーカーへ命令を送る。常駐プログラムが対象セッションのワーカーチャネルへ渡し、作業 Mac の Claude に流し込む
4. 作業 Mac の Claude が作業し、返信ツールで結果を返す。常駐プログラムがハブへ送る
5. ハブが秘書 Claude のセッションへ「どのワーカーのどのセッションからの結果か」の目印つきで流し込む
6. 秘書 Claude が返信ツールで利用者へ返す

### 4.2 スレッド（セッション）の作成と再開

Channels からは新しいスレッドを作れないため、常駐プログラムがプロセスの起動で代替する。

- 作成: 対象プロジェクトのフォルダで `claude --channels <worker-channel>` を tmux 内で起動。履歴はそのフォルダに紐づく
- 再開: 同じフォルダで `claude --resume <session-id>`。会話履歴とチャネル登録は維持される（検証 T10）
- 終了: tmux へ `/exit` を送る

### 4.3 承認と停止

| 場面 | 経路 | 備考 |
| --- | --- | --- |
| 通常ツール（Bash、Write、返信ツールなど）の承認 | ワーカーチャネルの permission relay → 常駐プログラム → ハブ → WebChat | 検証 T03/T04/T08 で成立 |
| CU のアプリ承認、開発用チャネルの起動時警告 | 端末ダイアログのみ。常駐プログラムが tmux 画面を読み取って WebChat に表示し、選択キーを送る | Channels の機能ではなく端末操作の代行 |
| 実行中の停止 | 常駐プログラムが tmux へ Esc を送る | 検証 T09。停止後は画面で実状態を確認する |

CU のアプリ承認はセッション起動時に 1 回で、同じアプリなら以後は不要（検証 T05〜T09）。
使うアプリを固定し、セッションを落とさずに保てば、日常の承認はほぼ発生しない。

## 5. 秘書 Claude から見えるツール（案）

| ツール | 引数 | 常駐プログラム側の動き |
| --- | --- | --- |
| `workers_status` | なし | ワーカーとセッションの一覧と状態 |
| `session_create` | worker, project, name | そのフォルダで Claude Code を起動 |
| `session_resume` | worker, session_id | 同じフォルダで `--resume` |
| `session_send` | worker, session_id, text | セッションのチャネルへ流し込む |
| `session_stop` | worker, session_id | `/exit` を送る |
| `session_interrupt` | worker, session_id | Esc を送る |
| `reply` | chat_id, text, in_reply_to | 利用者へ返信 |

命令は固定の種類にし、起動や停止に Claude の判断を挟まない。

## 6. 設定の方針

- 設定ファイルを唯一の正とし、設定画面はそれを読み書きする道具にする。ファイル直編集でも動く
- 秘密情報（WebChat トークン、ワーカーの接続鍵）は設定ファイルと分け、権限 600 のファイルか OS のキーチェーンに置く
- Claude Code 側の準備（`.mcp.json`、起動フラグ、CU の有効化、macOS の権限付与）は設定画面から変えられない。
  導入 CLI が書き込み、設定画面は「準備 OK／権限不足」の状態だけ表示する
- ワーカーの追加はペアリング方式（ハブが一時コードを発行し、作業 Mac で `pair <code>`）
- ワーカーの役割説明文はハブが `instructions` に組み込む。接続時に Claude へ渡されるため、変更後は再接続が必要

設定項目の棚卸しと型は `01-config-schema.md`（未作成）で確定する。

## 7. アカウントと運用上の注意

- 各 Mac の Claude Code は個別にログインする。Channels はアカウントを区別しない
- 同じアカウントを複数 Mac で使うと利用量の上限を共有する
- Team / Enterprise のアカウントは、管理者が組織設定で Channels を有効にする必要がある
- 仕事の作業内容がハブ Mac と秘書を経由する。会社の情報の扱いとして許されるかを先に確認する
- 無人設置ではスリープ禁止、自動ログイン、停電後の自動起動、自動更新の停止を行い、週 1 の点検で起動・承認をまとめて済ませる
- 想定外（新アプリの承認、セッション消失）に備え、SSH + tmux attach の安全網を各 Mac に用意する

## 8. 既知の制約（2026-10-12 時点）

- Channels は研究プレビュー。自作チャネルは `--dangerously-load-development-channels` が必要で、フラグ名と仕様は変更の可能性がある
- 公式の許可リストへの掲載は Anthropic のパートナー窓口経由。Team / Enterprise は管理者が自組織のリストに追加できる
- 1 台の Mac で CU を使えるセッションは同時に 1 つ（セッション終了までロック）
- `-p`（非対話モード）では Channels も CU も使えない。ワーカーは対話セッションで起動する
- 日本語 macOS では CU の `request_access` にアプリの表示名が通らない場合があり、bundle ID（`com.apple.TextEdit` など）で指定する
