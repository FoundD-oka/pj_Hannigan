# Hannigan 操作マニュアル（Phase 3: 同じ Mac でハブとワーカーを動かす構成）

作成日: 2026-10-17。画面は本物の Claude Code v2.1.301 で動かして撮影した（秘書・PM・子はすべて `--effort low`）。
対象: WebChat から統括秘書に仕事を頼み、案件 PM と子セッションの進み具合を見て、承認や停止をする人。
画面を撮り直すときは `bun scripts/manual-shots.ts <出力先>`（本物の Claude を使う。設定画面だけなら `--settings-only`、会話・スレッド・スマホ幅の見た目だけなら `--fake-chat` で、どちらも利用枠を使わない）。
2026-10-18 に画面の見た目を一新した（中央に寄せた会話欄、丸い入力欄、右上の「◐」で配色の切り替え、何も話していない会話では見出しと入力欄が画面の中央に出る）。1 章と 2 章の画面は新しい見た目で撮り直し済み。3 章以降の本物の Claude で撮った画面は前の見た目のままで、操作の位置と文言は変わっていない。

## 0. 用語

| 用語 | 意味 |
| --- | --- |
| ハブ | WebChat を配信し、秘書とワーカーの間を中継するプログラム。Phase 3 では手元の Mac で動く |
| 統括秘書（秘書） | WebChat の会話ごとに 1 つ起動する Claude Code。依頼の内容から担当の Mac と案件を選び、PM に指示する。画面では設定した名前（既定は Hannigan）で出る |
| ワーカー | 作業 Mac で動く常駐プログラム。Claude Code を tmux の中で起動・停止し、結果をハブへ返す |
| 案件 PM（PM） | 案件（フォルダ）ごとに 1 つの Claude Code。軽い作業は自分で行い、大きい作業は子セッションに任せる |
| 子セッション（子） | PM が作る作業用の Claude Code。報告は PM に届く |
| 承認カード | ツール実行や起動時の確認を WebChat に出したもの。ボタンで答える |
| 書込権 | 同じフォルダを書けるセッションを 1 つに絞る仕組み。順番待ちになると画面に「資源待ち」と出る |

## 1. 初回の準備（1 回だけ）

必要なもの: macOS、Bun 1.3 以降、tmux、claude.ai にログイン済みの Claude Code。

```bash
cd <リポジトリ>
bun install
scripts/start.sh
```

`start.sh` は設定が無ければ `~/.hannigan` に設定と鍵を作ってから、ハブとワーカーを tmux で起動する。最後に次のような 1 行が出る。

```text
WebChat (keep private): http://127.0.0.1:8800/#token=...
```

この URL をブラウザで開く。`#token=` の後ろは合言葉なので人に見せない。URL は 1 回開けばブラウザが覚える。

![初期画面](images/01-home.png)

右側の「スレッド」にワーカー（この Mac）と案件が出る。案件がまだ無いときは、2 章の設定画面で追加する。右上の「◐」で明るい配色と暗い配色を切り替えられる（既定は OS の設定に合わせる）。画面幅が狭いときは右上の「≡」で右側の一覧を開く。

## 2. 案件（フォルダ）を登録する

右上の「設定」を押す。いちばん上が話し相手のキャラ設定、次がハブの設定、下がワーカーごとの案件の設定。

### 2.1 話し相手の名前とキャラを決める

![設定画面（キャラ設定）](images/16-settings-persona.png)

| 項目 | 意味 | 変えるとき |
| --- | --- | --- |
| 名前 | 画面の見出しと返信の名札に使う。本人も自分の名前として名乗る。既定は Hannigan | 呼びたい名前があるとき |
| キャラ設定 | 性格、口調、話し方、やらないこと。毎回の返信で守らせる文章 | 最初に 1 回。合わなければ書き直す |
| あなたの呼び名 | 返信であなたをどう呼ぶか。空なら呼び名を使わない | 任意 |
| 返信の言語 | 空なら相手の言語に合わせる | 常に日本語にしたいときは「日本語」 |
| 返信の長さ | 短く（既定）、普通、詳しく | 報告が物足りないとき |
| 振り分けの判断基準 | どの Mac・どの案件に頼むかの決め方。ワーカーの「役割」と合わせて使う | Mac や案件が複数になったとき |
| 追加指示（上級） | 上の項目に収まらない指示 | 普段は空 |

「指示文のプレビュー」を開くと、次に起動する秘書に渡る全文を確かめられる。キャラ設定をどう書いても、振り分けの手順、依頼元の会話にだけ返す規則、結果を推測しない規則は変わらない。

「キャラ設定を保存」を押すと `hub.json` に書き込む。反映は次に秘書が起動したときなので、動いている会話の秘書は古い設定のまま動く。すぐ試したいときは、右の「Hannigan（会話ごと）」の一覧でその会話の「停止」を押し、次の発言で再開させる。名前だけは画面の表示にすぐ反映する。

### 2.2 ハブの設定

![設定画面（ハブ）](images/08-settings-hub.png)

| 項目 | 意味 | 変えるとき |
| --- | --- | --- |
| 同時に動かす秘書の数 | 会話ごとの秘書の上限。超えると、いちばん長く使っていない会話の秘書から止める | 利用枠を抑えたいとき |
| 放置で止めるまでの分 | 入力待ちの秘書を止めるまでの時間。再開は自動で履歴も残る | 既定の 30 分でよい |
| 保留を使う、期限、上限 | Mac が落ちている間の依頼をハブが預かる設定。期限は受付からの分数で、既定は 24 時間 | 普段は有効のまま |
| 表示名、役割 | 秘書が「どの Mac に振るか」を決める材料。役割は文章で書く | Mac を増やしたとき |

### 2.3 案件を追加する

下へスクロールすると案件の一覧がある。

![設定画面（ワーカーの案件）](images/09-settings-worker.png)

「案件を追加」を押して、案件 ID（英数字）、フォルダ（Mac 上の既存のフォルダ。`~/work/blog` のように書ける）、説明を入れ、「このワーカーの案件を保存」を押す。

![案件の追加](images/10-settings-add-project.png)

保存は即座に反映され、再起動はいらない。次のときは保存が断られる。

- フォルダが存在しない、相対パスで書いた
- 案件同士のフォルダが同じか入れ子になっている（書込権がフォルダ単位のため）
- PM や子が動いている案件を削除、またはフォルダを変更しようとした。先にスレッド一覧の「停止」で止める

「PM を使う」を外すと、その案件は PM 無しの Phase 2 方式（秘書が子を直接作る）になる。「PM の進め方」は、PM が自分で作業するか子に任せるかの基準で、既定の「状況で判断」でよい。

## 3. 仕事を頼む

会話画面の下の欄に、人に頼むように書いて送信する。案件 ID を文に入れると秘書が迷わない。

例: 「自宅 Mac の notes で、TODO.md を作って『買い物リストを作る』『来週の予定を整理する』の 2 行を書いて。小さい作業なので PM 自身でやって。終わったら一言で教えて」

### 3.1 起動時の確認に答える

その会話で初めて送ると秘書が起動し、承認カードが 2 枚出る。「フォルダの信頼確認」は trust を選ぶボタン、「開発用チャネルの起動確認」は「I am using this for local development」を押す。PM が起動するときにも同じカードが出る。

![起動時の確認](images/02-approval-startup.png)

右上の「未回答の承認 N」を押すと、答えていないカードへ飛ぶ。

### 3.2 ツールの承認

PM や子がファイルを書くときや、コマンドを実行するときに承認カードが出る。内容を見て「許可」か「拒否」を押す。拒否すると PM はその操作をあきらめて報告する。

![ツールの承認](images/03-approval-tool.png)

同じ操作で端末側にも「Create file」のような確認が出ることがある。これは Claude Code 本体の確認で、WebChat の承認を押すと端末側も進む。カードに「閉じました（画面から消えた）」と出れば答える必要はない。

### 3.3 結果が返る

PM が終わると「PM からの報告」が畳まれた形で出て、その下に秘書の返事が来る。報告の行を押すと PM の原文が開く。

![1 往復の結果](images/04-first-roundtrip.png)

薄い灰色の行は配送の記録。「届けました（処理完了ではありません）」は PM が受け取っただけの状態で、完了は報告で分かる。

### 3.4 PM が子に任せる

長い作業や並列の作業は、PM が子セッションを作って任せる。右側のスレッド一覧に子が増え、子の報告は PM に届き、PM がまとめて元の会話に返す。

![子への委任](images/05-delegation.png)

PM と子は同じフォルダを共有するので、片方が書いている間はもう片方は「資源待ち」になる。順番は自動で回る。

## 4. 進み具合を見る、直接口を挟む

右側のスレッド一覧で PM か子を押すと、そのセッションの履歴が出る。Claude Code の会話記録から発言、ツールの要約、ツールの結果を取り出して表示する（思考は出さない。秘密情報らしい文字列は伏せる）。

![PM のスレッド](images/06-thread-pm.png)

下の入力欄はこのスレッドへの直接投稿になり、秘書を通さずに PM に届く。子に投稿すると PM にも通知が行く。返事はこのスレッドに残り、秘書の会話には流れない。

![直接投稿](images/07-thread-direct.png)

「← 会話へ戻る」で秘書との会話に戻る。

## 5. Mac が止まっているときの依頼

ワーカーが落ちている間に依頼すると、ハブが預かって「保留中（Mac オフライン）」と出る。右側の「保留中の依頼」に並び、「取消」で取り下げられる。期限（既定 24 時間）を過ぎると実行されずに失効し、会話に通知が出る。

![オフライン保留](images/11-offline-hold.png)

ワーカーが戻ると受付順に配送され、通常どおり PM が動いて報告が返る。

![復帰後の配送](images/12-offline-delivered.png)

## 6. 止める、やり直す

スレッド一覧の各行にボタンがある。

| ボタン | 動き |
| --- | --- |
| Esc（中断） | 端末に Esc を送る。どこまで進んだかはスレッドで確認する |
| 停止 | セッションを終える。PM は次の依頼で履歴ごと再開する。秘書も同じ |

![PM を停止した状態](images/13-stopped.png)

書込権を持ったまま止められたセッションがあると、右側に赤い「要確認」の帯が出る。これは「作業が終わったか確かめられない」状態で、自動では解放しない。そのスレッドを開いて様子を見て、終わっていれば停止ボタンで止める。

画面幅が狭いと右側の一覧は隠れ、上の「スレッド」ボタンで開閉する。使い方は同じ。

## 8. 毎日の起動と終了

```bash
scripts/start.sh             # ハブとワーカーを起動。URL を表示
scripts/stop.sh              # ハブとワーカーだけ止める。Claude のセッションは tmux に残る
scripts/stop.sh --sessions   # 秘書・PM・子も /exit で終える
```

普段は `stop.sh` だけでよい。次の起動で秘書と PM は履歴ごと再開する。Mac の再起動前や Claude Code の更新後は `--sessions` で全部終える。

## 9. 困ったとき

| 症状 | 見る場所と対処 |
| --- | --- |
| 画面が「未接続」のまま | `tmux ls` に `hn-hub` と `hn-worker` があるか。無ければ `scripts/start.sh` |
| 秘書や PM が返事しない | `tmux attach -t hn-<案件>-<ID 先頭 8 桁>` で端末を直接見る。端末にしか出ない確認（Computer Use のアプリ承認など）が出ていることがある。見終わったら `Ctrl-b d` で抜ける |
| 承認カードが「閉じました（期限切れ）」になった | セッションを開き直すか、同じ依頼をもう一度送る |
| 赤い「要確認」の帯 | 6 章。該当スレッドを見て停止する |
| 原因を追いたい | `~/.hannigan/logs/hub.log` と `worker.log`。ハブの記録は `~/.hannigan/hub/`、ワーカーの記録は `~/.hannigan/worker/` |

## 10. 注意

- Claude Code Channels と純正 Computer Use は研究プレビュー。起動のたびに開発用チャネルの確認が出る
- 秘書・PM・子の 3 役ぶん利用枠を使う。最初は案件 1〜2 個で様子を見る
- トークン付きの URL と `~/.hannigan/secrets/` は人に見せない
- 画面に出る案件フォルダの場所は、この Mac の中でだけ使う。ハブの記録（イベント）には残らない

## 11. 2 台目の Mac をつなぐ

同じ LAN にあるもう 1 台の Mac を、作業用のワーカーとして足す手順。ハブ（WebChat と秘書）は 1 台目に置いたまま、2 台目はワーカーだけを動かす。2 台目の通信は SSH トンネル（SSH 接続の中に別の通信を通す仕組み）で 1 台目の `127.0.0.1:8800` に届くので、ハブのポートを LAN に公開しない。

同じ手順は WebChat の設定画面のいちばん下「2 台目の Mac をつなぐ（手順）」にも出る。1 台目で打つコマンドと、2 台目の Claude Code に貼るプロンプトの雛形（ポート、この Mac のホスト名と利用者名は埋めてある）が「コピー」ボタンつきで並ぶ。

![設定画面（2 台目の手順）](images/17-settings-second-mac.png)

**1 台目（ハブ側）で**

```bash
bun scripts/add-worker.ts --worker lime --name "Lime" --role "別の作業 Mac。登録された案件を実行"
```

ワーカー ID（英数字と `-` `_`、32 文字まで）、表示名、役割（秘書が振り分けに使う文章）を決めて実行する。鍵を 1 つ作って `~/.hannigan/secrets/worker-keys.json` に足し、`hub.json` の `workers[]` に項目を足す。画面に 2 台目で実行するコマンドが鍵つきで 1 回だけ出るので、そのまま控える（鍵は他のファイルやログには残らない）。同じ ID が既にあるときは断るので、鍵を作り直すときだけ `--force` を付ける（古い鍵は使えなくなる）。

ワーカー一覧はハブの起動時にしか読まないので、ハブを起動し直す。`stop.sh` はこの Mac のワーカーも止めるので、両方をもう一度起動する。

```bash
scripts/stop.sh && scripts/start.sh
```

次に、システム設定 > 一般 > 共有 > 「リモートログイン」をオンにして、2 台目から SSH で入れるようにする。

**2 台目（ワーカー側）で**

2 台目の作業は、その Mac の Claude Code に任せる。1 台目の `add-worker.ts` の出力の最後に「2 台目の Claude Code に貼るプロンプト」が鍵入りで出るので、2 台目で Claude Code を開いて、そのまま貼る。プロンプトの雛形は WebChat の設定画面の手順カード（4 番目）にもあり、1 台目のホスト名・利用者名・ポートは埋めてある。手元に鍵入りの出力が無いときは、雛形の `<ワーカー ID>` と `<鍵>` を埋めて貼る。

Claude は次を順に行い、各段階を報告する。sudo が要る操作や鍵の生成は実行前に確認を取る。

1. リポジトリを `~/pj-Hannigan` に取得して `bun install`
2. `bun scripts/worker-setup.ts --worker <ID> --key <鍵> --hub-port 8800` で `~/.hannigan/worker.json`（案件は空）と `secrets/worker-key` を書く。`hub.json` は作らない
3. `ssh -o BatchMode=yes <利用者名>@<1 台目>` で疎通を確かめる。鍵認証が無ければ `ssh-keygen` と `ssh-copy-id` を案内する（パスワードはあなたが入力する）
4. tmux セッション `hn-tunnel` で SSH トンネル（`-L 8800:127.0.0.1:8800`、`ServerAliveInterval` つき）を張り、`curl http://127.0.0.1:8800/health` で `{"ok":true}` を確かめる
5. `scripts/start.sh worker` で起動し、`~/.hannigan/logs/worker.log` の `connected to hub` を確かめる
6. 結果と変更したファイル、残った問題を報告する

Claude Code を使わないときは、プロンプトの中のコマンドを上から順に自分で実行すれば同じになる。プロンプトの本文は [shared/second-mac-prompt.ts](../../shared/second-mac-prompt.ts) にある。

**確認と案件の登録**

1 台目の WebChat を開くと、スレッド一覧に 2 台目のワーカーが表示名で出る。案件は 2 章と同じく設定画面で、2 台目のワーカーの欄に足す（フォルダは 2 台目の中の場所）。以後は秘書が役割を見て 1 台目と 2 台目を使い分ける。

| 症状 | 見る場所と対処 |
| --- | --- |
| 2 台目が「未接続」のまま | 2 台目の Claude に、tmux セッション `hn-tunnel` の `ssh` が生きているか、`~/.hannigan/logs/worker.log` に `connected to hub` が出ているかを確かめさせる |
| 1 台目の `hub.log` に `worker auth rejected` | 鍵が違う。1 台目で `add-worker.ts --worker <ID> --force` で作り直し、出てきた新しいプロンプトを 2 台目の Claude に貼り直す（`worker-setup.ts` には `--force` を付けるよう伝える） |
| 2 台目のワーカーが一覧に出ない | 1 台目のハブを起動し直したか（`stop.sh` と `start.sh`） |

この方式は Phase 3 のローカル実地テスト用。Phase 4 では VPS 上のハブに WSS でつなぎ、鍵はペアリングコードで交換する。
