# VPS の OpenMausBot から Mac の純正 Computer Use を使う

実施日: 2026-10-31 01:05〜01:35 JST
実施者: Claude Code（このリポジトリの開発セッション）。画面の操作は組み込みブラウザで行い、端末（tmux の中の Claude Code）には手で触れていない。
環境: VPS は OpenMausBot 0.1.127、Node 24.21.0、Caddy 2.6.2。Mac は M4 Mac mini（macOS 26.5.1）、Claude Code 2.1.311（Claude Max）、Bun 1.3.9、tmux 3.8。
設計: [05 OpenMausBot と Mac をつなぐ中継](../../design/05-omb-mac-relay.md)。[HANDOFF](../../HANDOFF.md) 5.1 の第 2 段階にあたる。

## 結論

`https://hannigan.found-d.com` の画面から、この Mac の純正 CU が一巡した。経路は「ブラウザ → VPS の OpenMausBot → 中継サーバー → wss → Mac の常駐プログラム → tmux の Claude Code」。第 1 段階で見つかった要対応 7 つのうち 6 つを解決し、1 つは回避策で動かしている（2 章）。

Mac の常駐プログラムは launchd で動いている。Mac の再起動からの復帰は確かめていない。2 台目の Mac も未接続。

| 確かめたこと | 結果 |
| --- | --- |
| 文字だけの 1 往復 | 成立。`OMB-MAC-1` が返った |
| 画面から依頼して純正 CU で作業 | 成立。`mcp__computer-use__request_access`、`open_application`、`screenshot`、`computer_batch`、`zoom` で TextEdit に `OMB-MAC-CU-1` を入力し、拡大して確かめた |

## 3. 見つかったこと

- launchd から起動した tmux では CU の macOS 権限がなかった（Accessibility、Screen Recording ともに未付与）。そこで常駐プログラムは launchd のまま、tmux サーバーの起動だけ Terminal.app に任せた（`relay/start-tmux-server.command`）。システム設定を変えずに、Terminal.app の付与済みの権限を引き継げる。代わりに、tmux サーバーを起動するたびに Terminal のウィンドウが開く
- 常駐プログラムを再起動すると、VPS の acp-client が接続を失ったまま残り、次の依頼に「オフライン」と答えるバグがあった。接続を失ったら終了するように直した。OpenMausBot が次の依頼で作り直す
- 新しいボットのエンジンは、`instances` に足した「Mac: m4-mini」が初期値になった。既存のボットは変わらない。表示名は試験のあとで「レモンm4」に変えた
- チャネルのツール承認（Bash など）は今回も発生しなかった。Claude Code の設定で許可済みのコマンドだった可能性がある。承認カードへの中継は未確認
- 接続を切る試験は VPS 側の TCP を切る形で、1 秒で戻った。長い切断は事前の確認の 15 秒まで。30 秒の通知と 15 分の打ち切りは未確認
- `request_access` にアプリ名 `TextEdit` を渡すと、日本語環境では見つからず結果に `notInstalled` が返る。Claude はバンドル ID で頼み直して通った

## 4. 確かめていないこと

- Mac の再起動（ログイン時の launchd の起動と、Terminal.app の起動）
- 2 台目の Mac。別ネットワークの Mac での CU
- iPhone からの CU の承認（カードの形は同じ）
- OpenMausBot 0.1.134 での動き（VPS は 0.1.127 のまま）
